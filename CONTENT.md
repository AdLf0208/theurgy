# Theurgy slice 1 — what the content mod carries, and what it declares

`content/` is generated by [`tools/assemble_content.py`](tools/assemble_content.py)
from the ATM10 jar (`ports/_shared/licence-cache/theurgy-1.21.1-neoforge-1.78.0.jar`,
SHA-256 `2165c808…2bc7dd`). `python3 tools/assemble_content.py --check` fails if
any of the 51 files drifts from the jar.

## Carried byte for byte (upstream's own assets, CC-BY-4.0)

| File(s) | What |
|---|---|
| `assets/theurgy/models/block/pyromantic_brazier.json`, `_template.json`, `_lit.json`, `_lit_template.json` | the brazier's Blockbench model and its lit variant (the lit one draws `minecraft:block/campfire_fire`) |
| `assets/theurgy/textures/block/pyromantic_brazier.png`, `_lit.png` | its two textures (128×128 UV atlases) |
| `assets/theurgy/models/item/pyromantic_brazier.json` | its item model, with the GUI display transform |
| `assets/theurgy/models/item/alchemical_salt.json`, `assets/theurgy/textures/item/alchemical_salt.png` | the one salt model and texture the five salts share |
| `data/theurgy/recipe/calcination_oven.json`, `pyromantic_brazier.json` | the two shaped recipes, with `#c:storage_blocks/copper`, `#c:ingots/iron`, `#c:ingots/copper`, `#c:stones` |
| the names and tooltip text of the two blocks and five items | from `assets/theurgy/lang/en_us.json` |

## Written by this port

| File(s) | Why |
|---|---|
| `data/theurgy/horizon/block/{calcination_oven,pyromantic_brazier}.json` | the two blocks on the **`minecraft:copper_block`** template (a plain full cube with no block entity of its own), with a declared `lit` boolean and upstream's `Properties`: hardness 1.0, blast resistance 1.0, `SoundType.COPPER` (`sounds: minecraft:copper_block`), `noOcclusion` (`occludes: false`), MapColor METAL (`map_color: 6`) |
| `data/theurgy/horizon/item/alchemical_salt*.json` | the five salts, `template: minecraft:gunpowder` (a plain 64-stack item, upstream's default components) |
| `assets/theurgy/items/*.json` | 26.3 item definitions; the four typed salts point at `theurgy:item/alchemical_salt`, the gas at the same model, the blocks at their block models |
| `assets/theurgy/blockstates/{calcination_oven,pyromantic_brazier}.json` | `lit=false|true`; the brazier's two carried models, the oven's **vanilla placeholder** (`minecraft:block/furnace` / `furnace_on`) because upstream draws it with a GeckoLib block-entity renderer |
| `assets/theurgy/lang/en_us.json` | the seven names. Upstream's item names are the `%s` template `item.theurgy.<salt>` plus `.source`; 26.3 content lang has no format arguments, so each is expanded ("Alchemical Salt Strata", "… Minerals", "… Plants", "… Creatures"); the generic `alchemical_salt` has no upstream name key at all and is named plainly |
| `data/theurgy/loot_table/blocks/*.json` | self-drop with 26.3's **singular typed** `minecraft:survives_explosion`; upstream's oven table drops only from `half=lower`, which the single-block port folds away |
| `data/theurgy/horizon/creative_tab/theurgy.json` | one tab with the seven items (upstream's tab is Java code) |
| `data/c/tags/item/*.json`, `data/theurgy/tags/item/other_minerals.json` | the 19 item tags the calcination and crafting recipes name, with the members [`tools/tag_members.json`](tools/tag_members.json) resolved (26.3 vanilla tags, NeoForge's generated `c:` tags, the jar's own tags) |
| `horizon-mod.toml` | `id = "theurgy"`, version **0.1.0** (the port's own), `api = "0.2"`, `side = "both"`, `capabilities = ["registries"]` |

## Not carried (gaps, in `notes.md`)

Everything else the jar holds: the other 23 blockstates (distiller,
liquefaction cauldron, the vats, the incubator, the pedstals, the logistics
nodes, the ores, the catalysts), 388 of the 393 item models (sulfurs, niters,
mercury, jars, rods, filters), 1,691 of the 1,777 recipes (the nine other
recipe types), 23 loot tables, 9 advancements, 100 Modonomicon pages, the GUI
textures and the GeckoLib renderers.

The five **sulfurs / mercury / niters** are deliberately left out: this slice is
calcination only, and shipping the other principles without their processes
would be content without behaviour.
